# Accelerator ⇄ server protocol

Sources: `extension/extension.cpp` from [asherkin/accelerator](https://github.com/asherkin/accelerator)
(client side, the one that dictates the protocol) and `src/Throttle/Crash.php` / `Symbols.php` from the `php-final` tag
(legacy server side). The new server must be compatible with **the client**, not with the PHP.

## Client configuration (`addons/sourcemod/configs/core.cfg`)

| Key | Default | Use |
|---|---|---|
| `MinidumpUrl` | `http://crash.limetech.org/submit` | presubmit and upload |
| `MinidumpSymbolUrl` | `http://crash.limetech.org/symbols/submit` | `.sym` upload |
| `MinidumpBinaryUrl` | `http://crash.limetech.org/binary/submit` | binary upload (only if the server asks for `U`) |
| `MinidumpPresubmit` | yes | if `n`/`0`, skips the presubmit and uploads everything |
| `MinidumpSymbolUpload` | `3` | 0 off, 1 system, 2 +game, 3 +addons |
| `MinidumpBinaryUpload` | yes | allows `U` |
| `MinidumpAccount` | empty | owner's SteamID64, becomes `UserID` |

## Client flow (per dump in `data/dumps/*.dmp`)

1. If presubmit is on: process the dump locally and `POST MinidumpUrl` with `CrashSignature`.
2. Decide based on the response (table below).
3. Upload the symbols/binaries the server asked for (module by module).
4. Upload the dump + metadata.
5. **Always delete the local dump at the end**, whether it was uploaded or not.

### Presubmit: `POST /submit` (form-urlencoded/multipart)

Fields: `UserID` (optional), `ExtensionVersion`, `ServerID` (UUID v4 generated by the client), `CrashSignature`.

`CrashSignature` (version 2), fields separated by `|`:

```text
2|<timestamp>|<os_short>|<cpu>|<crashed 0/1>|<crash_reason>|<crash_address hex>|<requesting_thread>
  (|M|<debug_file>|<debug_identifier>)*      one per module, in index order
  (|F|<module_index>|<offset hex>)*          up to 1024 frames of the crashed thread; index -1 = no module
```

Versions 0 and 1 (legacy) omit `timestamp|os|cpu`. The legacy server accepts 0–2.

**Response** (plain text, trailing `\n` is ignored by the client):

```text
<K>|<module flags>[|<token>]
```

* `K` (1st byte): `Y` sends dump+metadata · `M` sends **metadata only** · `N` sends nothing · `E` error.
* `|` is mandatory at the 2nd byte.
* `module flags`: **exactly one character per module in the signature, in the same order.**
  `Y` = send this module's `.sym` (Linux only) · `U` = send the binary · anything else = nothing.
  If fewer characters than modules arrive, the client ignores flags and token (logs "Response module list doesn't match").
* `token` (optional, < 512 bytes, up to the next `|`): the client resends it as `PresubmitToken` in all following uploads.
  **The client prints the token in the log as `Got a presubmit token from server: …`**; that is how the message
  "Sorry, crash submission is currently disabled (capacity reached)" showed up: the public server answered
  `N|<flags>|Sorry, …` and the text landed in the token field.
* A response shorter than 2 bytes, or a first byte outside `Y/N/M/E`, or `E|msg` ⇒ **remote error**.

### How the client reacts (critical point for the design of limits)

| Situation | Client action | Local dump |
|---|---|---|
| `Y` | uploads dump + metadata | deleted |
| `M` | uploads metadata only (no `upload_file_minidump`) | deleted |
| `N` | "Skipped due to server request" | deleted |
| `E…`, short response, HTTP ≠ 2xx, network failure on presubmit | **carries on and tries to upload the dump anyway** | deleted |
| HTTP ≠ 2xx on upload (e.g. 503) | logs "Failed to upload crash dump" | **deleted, no retry** |

Consequences:

* The client **does not retry and does not honor `Retry-After`.** Any refusal (`N`, `M`, 4xx, 5xx) = the crash
  is lost forever. Refusing is only acceptable as a last resort.
* That is why the new server **accepts cheaply and discards later** (writes to disk, queue in the DB, eviction by
  quota) instead of refusing at the door. `503` only when the disk is truly out of space.
* `SetFailOnHTTPError(true)`: the client treats 4xx/5xx as errors; a `200` with an error text
  (e.g. `Rate limit exceeded.`) is logged as "Uploaded crash dump: Rate limit exceeded." (success).
  That is what the legacy does today and the client accepts it.

### Upload: `POST /submit` (multipart)

| Field | Notes |
|---|---|
| `UserID` | optional. `0`/absent ⇒ anonymous. Accepts SteamID64 (`ctype_digit` and `(id & 0xFFFFFFFF00000000) == 76561197960265728`) or `STEAM_X:Y:Z` (converted). Invalid ⇒ treated as anonymous. |
| `GameDirectory`, `ExtensionVersion`, `ServerID`, `PresubmitToken` | go into the metadata JSON (`PresubmitToken` is currently discarded) |
| `upload_file_minidump` | the `.dmp` (absent in `M` mode) |
| `upload_file_metadata` | the `.dmp.txt`, see format below |
| `prod` | standard Breakpad uploader (Electron etc.): the response is a UUID, see "IDs" |

**Success response:** `Crash ID: XXXX-XXXX-XXXX` (uppercase ID, groups of 4, **no** trailing `\n`).
The client keeps up to 511 bytes of this and exposes it to SourcePawn plugins (`Accelerator_GetUploadedCrash*`).

**Repeated crash (rewrite).** If a crash with the same presubmit fingerprint (`CrashSignature`) from the same owner (anonymous: same address) already exists within `limits.repeat_window_days`, the presubmit answers `M` and the upload does not create a new crash: the server increments `repeats` on the existing one and answers with **its** ID, in the same format. The fingerprint travels in the signed `PresubmitToken`, so an upload without a valid token is never counted as a repeat. The client notices no difference.

**Legacy rejection responses (all `200`):**

| Case | Body |
|---|---|
| no valid/empty minidump | `A problem with your host is preventing crash reports from being generated.\n` |
| an `nosteam-*` notice crash from the same owner+IP in the last month | `Servers that support piracy are not welcome.` |
| owner+IP with a crash that got a `nosteam-*` notice in the last 30 days | `Servers that support piracy are not welcome.` |
| more than 12 crashes in the last hour from the same owner+IP | `Rate limit exceeded.` |

### Metadata file format (`upload_file_metadata`)

```text
-------- CONFIG BEGIN --------
Map=…
GamePath=…
CommandLine=…
SourceModPath=…
GameDirectory=…
SourceModVersion=…          (optional)
ExtensionVersion=…
ExtensionBuild=…
Steam_<key>=<value>         (steam.inf lines, e.g. Steam_PatchVersion=…)
-------- CONFIG END --------
-------- CONSOLE HISTORY BEGIN --------
…
-------- CONSOLE HISTORY END --------
```

* Each `Key=Value` in the CONFIG block overrides the form field of the same name (an empty value is ignored).
* `CommandLine` is stored separately (`crash.cmdline`), with sanitized UTF-8 (invalid → U+FFFD).
  On display, the value after `+sv_password`, `+rcon_password`, `+sv_setsteamaccount` becomes `*****`.
* If the CONSOLE block exists and is not empty ⇒ `HasConsoleLog=true` in the metadata.
* The whole raw file is stored compressed (`<id>.meta.txt.gz`).
* The CONFIG block may contain arbitrary bytes: the legacy regex uses `[^\x00]+`. Treat as bytes, not `String`.
* `ExtensionBuild` is hidden on display.

## Symbols: `POST /symbols/submit`

Fields: `symbol_file` (or the raw request body), plus `UserID`, `ExtensionVersion`, `ServerID`, `PresubmitToken`.
The client only uploads symbols for modules the presubmit answered `Y` for (Linux). Accelerator's CI
also does a `POST` with the raw body (`Content-Type: text/plain`).

* The 1st line must match `^MODULE <os> <arch> <id hex> <name without / or \>$`; otherwise `400 Invalid symbol file`.
* `os == Linux` requires at least one `FUNC` before the first `STACK`; otherwise
  `400 Symbol file had no FUNC records, please update to Accelerator 2.4.3 or later`.
* Stored at `symbols/public/<name>/<id>/<name without .pdb>.sym.gz`.
* Success: `Stored symbols for <name>/<id>/<os>/<arch>\n`.
* The new server must **validate** `name` and `id` (they already rule out `/` and `\`; keep that and test `..`).

## Binaries: `POST /binary/submit`

Only called if the presubmit returned `U` for some module. The legacy **never implemented it**.
The new server **never answers `U`** ⇒ the client never calls this endpoint. Log a 404 if anyone calls it.

## IDs

* Crash ID: 12 characters, alphabet `a-z2-7` (lowercase base32, 60 bits). The route accepts `[0-9a-zA-Z]{12}`;
  the web normalizes to lowercase and strips `-`.
* **UUID ⇄ ID** (Breakpad uploader with `prod=1`): `UUID = "bee0cafe-0000-4000-" + hex(bytes[0..2]) + "-" + hex(bytes[2..8])`,
  where `bytes` are 64 bits = `1000` (RFC 4122 variant) ++ 12×5 bits of the ID. Reversal (0-based indexes in the 36-char string):
  nibble 19 is always `8` (variant) and is ignored; join chars 20–22 and 24–35 (3 + 12 nibbles = 60 bits)
  and regroup into 12 symbols of 5 bits.
  The legacy uses the UUID as the `/{uuid}` route (`[0-9a-fA-F-]{36}`) and redirects to `/{id}`.

## New server presubmit (decision)

Keeps the client's semantics and uses the only soft valve it offers:

| Condition | Response |
|---|---|
| normal | `Y\|<flags>\|<token>` |
| stackhash already seen many times / queue above the *watermark* | `M\|<flags>\|<token>` (counts the crash, does not pay for the dump) |
| rate limit exceeded (owner+IP) | `N\|<flags>\|<message>` |
| owner+IP blocked by a `nosteam-*` notice | `N\|<flags>\|Servers that support piracy are not welcome.` |
| disk out of space even after eviction | HTTP 503 (the client will try the upload and fail just the same) |

`<flags>`: `Y` for Linux modules with no `.sym` present, `N` otherwise. Never `U`.
The token is a short HMAC (`ts|hash` with a server secret), not `md5` as in the legacy, and is validated on upload
to apply the same decision as the presubmit.

## Known legacy → new differences

* The legacy returns `Y|` + `N/Y` per module and `md5` as the token. The new one keeps the shape and changes the token.
* The legacy only has `Y`. The new one adds `M` and `N`.
* The legacy's limits were fixed in code. In the new one, all are configurable (see `deploy/config.example.toml`).
